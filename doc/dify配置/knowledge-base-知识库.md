# 知识库配置说明

> 适用：Dify **知识库**，供聊天助手检索使用。
> 知识库与聊天助手在 Dify 中通过「上下文」关联。

---

## 一、知识库定位

知识库是数字人回答景区问题的**唯一事实来源**。聊天助手不会凭空编造信息——所有关于景区的内容必须来自知识库。

### 1.1 数据流

```
知识库文档 ──检索──→ Chat Agent ──流式输出──→ 数字人播报
                              ↑
                         提示词约束：
                    「优先使用知识库内容」
```

### 1.2 赛题要求

| 要求 | 指标 | 验证方式 |
|------|------|----------|
| 知识库问答准确率 | ≥ 90% | 准备 50+ 条测试问答，逐一验证 |
| 景区资料覆盖 | 景点、路线、票务、设施、开放时间 | 检查知识库文档清单 |

---

## 二、文档结构设计

### 2.1 推荐文档拆分

按内容类型拆分为独立文档，避免单文件过大影响检索精度：

```
知识库文档/
├── 01-景区概览.md          # 景区简介、地理位置、历史背景
├── 02-景点介绍.md          # 各景点详细介绍
├── 03-游览路线.md          # 推荐路线（含时间规划）
├── 04-票务信息.md          # 门票价格、优惠政策、购票方式
├── 05-开放时间.md          # 开放/关闭时间、最佳游览季节
├── 06-交通指南.md          # 到达方式、内部交通、停车场
├── 07-设施服务.md          # 卫生间、餐饮、寄存、Wi-Fi、轮椅等
├── 08-常见问题.md          # FAQ（游客高频问题）
├── 09-推荐矩阵.md          # 景点 × 年龄段推荐数据
└── 10-安全须知.md          # 游览安全提示、紧急联系方式
```

### 2.2 文档编写原则

#### 结构化段落
每个文档按「标题 → 小标题 → 正文段落」组织，方便检索时定位：

```markdown
# 日光岩

## 简介
日光岩是鼓浪屿最高点，海拔92.68米，...

## 特色
- 登顶可360°俯瞰鼓浪屿和厦门岛
- 日出时分景色最佳
...

## 游览建议
建议清晨或傍晚前往，避开正午高温。游览时间约1小时。

## 门票
包含在鼓浪屿联票内，单独购票50元/人。
```

#### 信息密度
- 每个段落应**自包含**——被检索到时不需要上下文也能理解
- 避免跨段落的引用（如「如上所述」「详见上文」）
- 关键信息（价格、时间、电话）放在段落开头

#### 命名规范
- 景点名使用完整官方名称（如「日光岩」不是「那个岩石」）
- 地名、设施名称全文统一，避免同义词
- 数字使用阿拉伯数字（如「3小时」不是「三个小时」）

## 三、分段策略

### 3.1 推荐参数

在 Dify 知识库「设置」中：

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 分段方式 | 自动分段与清洗 | Dify 默认 |
| 分段最大长度 | 500 tokens | 每段约 200-300 个中文字 |
| 分段重叠长度 | 50 tokens | 相邻段有少量重叠，防止边界截断 |
| 索引方式 | 高质量 | 消耗更多 token 但准确率更高 |

### 3.2 特殊内容的分段处理

#### 表格数据（景点 × 年龄段推荐矩阵）

表格在自动分段时容易被打散。推荐改为列表格式：

```markdown
# 景点推荐矩阵

## 日光岩
- 青少年（12-18岁）：★★★★★ 推荐 — 登高望远，充满探索感
- 青年（19-35岁）：★★★★★ 推荐 — 拍照打卡首选，视野绝佳
- 中年（36-55岁）：★★★★ 推荐 — 需一定体力，建议早晨前往
- 老年（56岁以上）：★★★ 一般 — 台阶较多，需量力而行
- 亲子（带儿童）：★★★★ 推荐 — 小朋友会喜欢登高体验
```

#### FAQ 内容

每个问答对作为一个独立段落：

```markdown
# 常见问题

## Q: 景区有行李寄存服务吗？
A: 有。景区入口和游客中心均提供行李寄存服务，小件5元/次，大件10元/次。寄存时间8:00-18:00，请于当天闭园前取回。

## Q: 景区可以带宠物吗？
A: 抱歉，为保障游客安全和景区卫生，宠物（导盲犬除外）不能带入景区。景区入口处设有宠物临时寄放点。
```

## 四、推荐矩阵（景点 × 年龄段）

### 4.1 数据说明

知识库中的「景点 × 年龄段 → 推荐程度」数据是**个性化推荐**的基础。当游客提及自己的年龄段或同行人员时，Chat Agent 能据此给出精准推荐。

### 4.2 推荐等级定义

| 等级 | 含义 | Agent 应如何推荐 |
|------|------|-----------------|
| ★★★★★ 强烈推荐 | 该年龄段首选景点 | 主动推荐，作为核心行程 |
| ★★★★ 推荐 | 适合该年龄段的优质景点 | 列入推荐清单 |
| ★★★ 一般 | 可以去，无特别优劣 | 根据时间安排是否纳入 |
| ★★ 不推荐 | 不太适合该年龄段 | 说明原因，建议替代景点 |
| ★ 强烈不推荐 | 安全或体验风险 | 明确告知不适合，并解释原因 |

### 4.3 年龄段划分

| 年龄段 | 标签 | 典型场景 |
|--------|------|----------|
| 亲子（带儿童 3-12 岁） | `亲子` | 家庭出游，关注安全性、趣味性、儿童设施 |
| 青少年（12-18 岁） | `青少年` | 研学/同学出游，关注探索性、互动性 |
| 青年（19-35 岁） | `青年` | 朋友出游/情侣，关注拍照打卡、网红体验 |
| 中年（36-55 岁） | `中年` | 家庭出游/团建，关注舒适度、文化内涵 |
| 老年（56 岁以上） | `老年` | 退休出游，关注体力消耗、无障碍设施 |

### 4.4 数据模板

为每个景点填写以下模板：

```markdown
# [景点名称] — 年龄段推荐

- **亲子**：[推荐等级] — [简要理由，1句话]
- **青少年**：[推荐等级] — [简要理由]
- **青年**：[推荐等级] — [简要理由]
- **中年**：[推荐等级] — [简要理由]
- **老年**：[推荐等级] — [简要理由]
- **特色提示**：[该景点的特别注意项，如「台阶较多」「需预约」「有表演时段」]
```

## 五、测试验证

### 5.1 准确率测试集

准备至少 50 条测试问答，覆盖以下类别：

| 类别 | 示例问题 | 预期 |
|------|----------|------|
| 景点介绍 | 「XX景点有什么特色」 | 准确描述景点核心信息 |
| 票务查询 | 「门票多少钱」「有学生票吗」 | 准确回答价格和优惠政策 |
| 开放时间 | 「几点开门」「国庆节营业吗」 | 准确回答时间信息 |
| 路线推荐 | 「推荐一条半日游路线」 | 给出合理路线建议 |
| 设施指引 | 「有停车场吗」「卫生间在哪」 | 准确回答设施位置和使用方式 |
| 推荐矩阵 | 「带老人去推荐什么」 | 结合年龄段给推荐 |
| 边界问题 | 「XX景点海拔多高」（知识库无此数据） | 诚实告知暂无数据 |

### 5.2 测试方法

1. 在 Dify 聊天助手「预览」中逐条输入测试问题
2. 记录回答是否正确、是否引用知识库片段
3. 统计准确率：正确回答数 / 总测试数 ≥ 90%
4. 对回答错误的问题，检查知识库是否缺少对应内容，补充后重新测试

### 5.3 优化迭代

| 问题现象 | 可能原因 | 修复方向 |
|----------|----------|----------|
| 回答不完整 | 分段截断了关键信息 | 调整分段长度或重组文档结构 |
| 检索不到相关内容 | 关键词不匹配 | 在文档中补充同义词/口语化表述 |
| 回答准确但啰嗦 | 检索返回了无关片段 | 提高相似度阈值或减少 Top K |
| 回答编造信息 | 知识库无相关内容 + 提示词约束不足 | 强化提示词中的边界规则 |
| 表格数据检索失败 | 分段打散了表格 | 改为列表格式重新上传 |

## 六、维护流程

### 6.1 内容更新

1. 修改源文档（Markdown 文件）
2. 在 Dify 知识库中「更新文档」
3. 等待重新索引（通常 1-2 分钟）
4. 在预览中验证更新后的回答

### 6.2 版本管理

建议将知识库 Markdown 源文件纳入 Git 管理：

```
doc/
└── knowledge-base/         # 知识库源文档（建议新建此目录）
    ├── 01-景区概览.md
    ├── 02-景点介绍.md
    ├── ...
    └── 10-安全须知.md
```

每次修改知识库内容时提交 commit，方便回溯。

### 6.3 常见问题补充

定期查看数据大屏的「热门关注点」（hot_issues），如果反复出现某个问题分类，说明该领域可能缺少知识库覆盖，应及时补充。
