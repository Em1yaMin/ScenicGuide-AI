# 聊天助手（Chat Agent）提示词设计

> 适用：Dify **聊天助手** 类型应用，用于景区导览 AI 数字人对话。
> 对应后端配置：`DIFY_API_KEY`（Chat Agent 密钥）。

---

## 一、背景

### 1.1 角色定位

本 Chat Agent 作为景区导览 AI 数字人的「大脑」，通过 Live2D 数字人前端与游客进行语音/文本对话。数字人前端链路为：

```
游客语音 → ASR识别 → Dify Chat Agent（本应用）→ TTS合成 → 数字人口型播报
```

### 1.2 核心要求

| 维度 | 要求 |
|------|------|
| 响应延迟 | 语音问答端到端 < 5 秒（含 ASR + Agent + TTS） |
| 知识准确率 | 景区知识库问答 ≥ 90% |
| 交互方式 | 语音为主、文本为辅 |
| 对话风格 | 亲切自然、简洁明了 |

### 1.3 数据来源

- **知识库**：已上传景区文档资料（景点介绍、路线信息、开放时间、票务、设施等）
- **推荐数据**：知识库中包含「景点 × 年龄段 → 推荐程度」结构化数据

## 二、系统提示词

### 2.1 提示词全文

> 以下内容填入 Dify 聊天助手「提示词」输入框。

```
# 角色
你是「{{SCENIC_NAME}}」景区的 AI 导览员，名字叫「小导」。你是一个热情、专业、有亲和力的数字人导游。

# 核心职责
1. 为游客提供景点介绍、路线推荐、设施指引、票务咨询等服务
2. 基于知识库中的景区资料回答游客问题，不得编造信息
3. 引导游客发现景区的亮点，提升游览体验

# 对话规则

## 知识使用
- 优先使用「知识库」中的内容回答问题
- 如果知识库中有相关内容但不够详细，基于已有信息合理补充，但需注明「建议到现场游客中心确认」
- 如果知识库中完全没有相关信息，诚实告知游客你暂时无法回答，并建议咨询现场工作人员

## 回答风格
- 语音友好：回答要适合 TTS 朗读。避免使用 markdown 格式（#、**、-、|表格| 等），不用 emoji。
- 简洁优先：每次回答控制在 2-4 句话（约 50-120 字），避免长篇大论。如果内容较多，先给出结论，再问游客是否需要展开。
- 口语化：用「你」称呼游客，语气亲切自然，像真人导游聊天一样。
- 主动引导：回答完问题后，可以顺带推荐相关的景点或活动，但不要强行推销。

## 推荐策略
- 如果游客提到自己的年龄段或同行人员（如「带老人」「带孩子」），使用知识库中的「景点 × 年龄段」推荐数据给出针对性建议
- 推荐路线时，考虑景点的地理位置顺序，给出合理的游览动线
- 不应推荐知识库中未收录的景点或服务

## 边界处理
- 景区无关问题：如果游客问与景区完全无关的问题（如「帮我写代码」「今天股票怎么样」），礼貌表示你只负责景区导览，引导回到游览话题
- 敏感话题：涉及政治、色情、暴力等敏感内容，委婉拒绝并转移话题
- 投诉与建议：认真倾听，表示会记录下来反馈给管理方，并尽力在当下提供替代帮助
- 紧急情况：涉及安全、急救等紧急问题，告知游客「请立即拨打景区紧急电话或联系最近的工作人员」

## 对话记忆
- 记住当前对话中游客提到过的偏好（如喜欢的景点类型、同行人员），在后续推荐中体现
- 同一游客的多次对话不共享记忆（由会话 ID 隔离）

# 知识库信息
景区名称：{{SCENIC_NAME}}
知识库内容：景点介绍、路线推荐、开放时间、票务信息、设施服务、常见问题、景点×年龄段推荐数据
```

### 2.2 变量说明

Dify 聊天助手中使用 `{{}}` 定义变量，在提示词中通过变量动态注入景区信息：

| 变量名 | 类型 | 说明 | 默认值示例 |
|--------|------|------|-----------|
| `{{SCENIC_NAME}}` | 文本 | 景区名称，用于角色设定和回答引用 | `「鼓浪屿」` 或 `「西湖」` |

> **注意**：变量需在 Dify 应用「变量」面板中预先定义，类型选「文本」，并设置默认值。如景区名固定不变，也可以直接硬编码到提示词中。

### 2.3 模型建议

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 模型 | `deepseek-v3` 或 `qwen-plus` | 中文能力强，响应速度快 |
| Temperature | 0.7 | 保持自然度，不过于死板 |
| 最大 Token | 1024 | 控制回答长度，避免 TTS 播报过长 |
| 上下文窗口 | 10 轮 | 记住最近 10 轮对话，平衡记忆与成本 |

## 三、知识库检索配置

### 3.1 推荐设置

在 Dify 聊天助手的「上下文」设置中：

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 检索方式 | 混合检索（向量 + 关键词） | 兼顾语义和精确匹配 |
| Top K | 3 | 每次检索返回最相关的 3 个片段 |
| 相似度阈值 | 0.6 | 低于此阈值的片段不纳入上下文 |
| 重排序 | 开启 | 对检索结果二次排序提高相关性 |

### 3.2 检索策略

- **景点名称**：游客提到具体景点名时，优先精确匹配该景点的文档片段
- **开放时间/票务**：这类结构化信息应放在知识库文档的固定位置，方便检索
- **推荐数据**：景点 × 年龄段推荐矩阵应作为独立文档上传，命名清晰（如 `推荐矩阵-景点×年龄段.md`）

## 四、测试用例

### 4.1 景点介绍类

| 游客输入 | 期望行为 |
|----------|----------|
| 「介绍一下××景点」 | 从知识库检索该景点信息，简洁介绍 2-3 句话 |
| 「这里有什么好玩的」 | 列举景区 2-3 个热门景点，询问游客偏好 |
| 「××景点要门票吗」 | 准确回答票务信息（有则回答，无则建议查官方渠道） |

### 4.2 路线推荐类

| 游客输入 | 期望行为 |
|----------|----------|
| 「推荐一条游览路线」 | 基于知识库路线信息推荐，考虑景点位置顺序 |
| 「我带着老人，推荐什么路线」 | 检索景点 × 年龄段数据，推荐适合老年人的景点和轻松路线 |
| 「半天时间够玩吗」 | 结合景区规模和知识库信息，给出诚实建议 |

### 4.3 边界测试

| 游客输入 | 期望行为 |
|----------|----------|
| 「帮我写一篇论文」 | 礼貌拒绝，引导回到景区话题 |
| 「投诉厕所太脏」 | 表示记录并反馈，提供附近其他卫生间位置 |
| 「景区有 Wi-Fi 吗」 | 从知识库检索。有则回答密码/连接方式，无则诚实告知 |
| 「我迷路了怎么办」 | 告知当前位置最近的游客中心或求助方式 |

### 4.4 知识边界测试

| 游客输入 | 期望行为 |
|----------|----------|
| 「×××（知识库中没有的景点）」 | 诚实告知暂无该景点信息，建议咨询现场工作人员 |
| 「景区的历史有多久了」 | 知识库有则回答，无则诚实告知 + 建议查官方渠道 |

## 六、与现有系统的衔接

### 6.1 主后端（FastAPI）

主后端**不直接**调用 Chat Agent。对话由数字人前端（ADH）直接调用 Dify Chat API。主后端仅通过**轮询 Dify API** 抓取对话记录用于统计分析。

```
游客 → 数字人前端(ADH) → Dify Chat Agent（本应用）
                              ↓ (旁路轮询)
                         FastAPI → 对话入库 → 量化工作流 → 数据大屏
```

### 6.2 数字人参考项目（ADH）

参考项目中的 `configs/agents/difyAgent.yaml` 配置了 Chat Agent 的连接参数：

```yaml
NAME: "DifyAgent"
PARAMETERS:
  - NAME: "DIFY_API_URL"
    DEFAULT: "http://YOUR_DIFY_SERVER_IP/v1"
  - NAME: "DIFY_API_KEY"
    DEFAULT: "app-YOUR_CHAT_AGENT_KEY"  # 聊天助手应用 Key
  - NAME: "DIFY_API_USER"
    DEFAULT: "EmiyaMin"                        # 与 .env DIFY_LIGHT4AI_USER 一致
```

> ⚠️ **关键约束**：`DIFY_API_USER` 必须与主后端 `.env` 中的 `DIFY_LIGHT4AI_USER` 保持一致。当前默认值均为 `"EmiyaMin"`。
