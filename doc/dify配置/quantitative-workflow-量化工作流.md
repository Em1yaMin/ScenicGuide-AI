# 量化评估工作流设计

> ⚠️ **已 superseded（阶段4 首项，2026-08-07 船长决策方案A）**：量化评估已改为**本地 LLM**（`app/services/evaluation_service.py`，复用 `LLM_*` 配置 opencode-go），**不再调用 Dify Workflow**，`DIFY_WORKFLOW_API_KEY` 与 `dify_client.trigger_workflow` 已移除。本文档仅作为历史设计与提示词存档保留（提示词语义已移植到 `evaluation_service._EVALUATION_SYSTEM_PROMPT`）。

> 适用：Dify **工作流** 类型应用，用于对景区数字人对话进行量化分析。
> 对应后端配置：`DIFY_WORKFLOW_API_KEY`（Workflow 密钥，已移除）。

## 一、背景

### 1.1 工作流定位

量化评估工作流在整个系统中的角色：

```
FastAPI 轮询 Dify → 对话入库(dialogues表)
                         ↓ (每 5 分钟批量)
                   调用本工作流 → 分析结果 → 入库(evaluations表)
                                              ↓
                                    数据大屏 + 感受度报告
```

### 1.2 后端调用方式

主后端通过 `dify_client.trigger_workflow()` 调用本工作流，代码路径如下：

```python
# digitalHumanApi/app/services/dify_client.py:125
result = await dify_client.trigger_workflow({"input": dialogue.content})

# digitalHumanApi/app/tasks/analysis.py:60-65
raw_output = result.get("data", {}).get("outputs", {}).get("text", "")
parsed = _parse_workflow_output(raw_output)
```

**关键约束**：
- 调用方式：`POST /workflows/run`，`response_mode: "blocking"`（同步等待结果）
- 输入字段名：`input`（对应对话文本内容）
- 输出字段名：`text`（对应 LLM 节点输出的 JSON 文本）
- 输出格式：JSON 字符串（可包裹在 ```json ``` 代码块中，后端会自动剥离）

### 1.3 期望输出结构

后端 `evaluate_dialogue()` 解析以下字段（详见 `app/tasks/analysis.py:68-92`）：

| 字段名 | 类型 | 必需 | 说明 |
|--------|------|------|------|
| `sentiment_label` | string | 是 | 情感标签：`positive` / `negative` / `neutral` |
| `satisfaction_score` | int | 是 | 满意度评分：1-5 整数 |
| `concern_tags` | string[] | 是 | 关注点标签列表，如 `["票务咨询", "路线规划"]` |
| `mentioned_spots` | string[] | 是 | 对话中提及的景点名称列表 |
| `suggestions` | string[] | 否 | 改进建议列表（用于感受度报告） |

> **容错设计**：代码同时接受字段别名（`sentiment`→`sentiment_label`，`concerns`→`concern_tags`，`spots`→`mentioned_spots`），但不建议依赖别名。

## 二、工作流结构

### 2.1 节点拓扑

```
┌─────────┐     ┌─────────────────┐     ┌───────────┐
│  Start  │────▶│  LLM 量化分析    │────▶│   End     │
│ (input) │     │  (核心 Prompt)   │     │  (text)   │
└─────────┘     └─────────────────┘     └───────────┘
```

**单 LLM 节点设计** — 原因：

| 方案 | 调用次数 | 成本 | 复杂度 | 适用 |
|------|---------|------|--------|------|
| **单 LLM（推荐）** | 1 次/对话 | 1x | 低 | 当前选择 |
| 多 LLM 并行 | N 次/对话 | Nx | 高 | 精度要求极高时 |

赛题单人开发、API 成本敏感的约束下，选择单 LLM 节点方案。

### 2.2 节点配置

#### Start 节点

| 参数 | 值 |
|------|-----|
| 类型 | 开始 |
| 输入变量 | `input` — 文本类型，对话内容 |

#### LLM 节点

| 参数 | 值 |
|------|-----|
| 名称 | `量化分析` |
| 模型 | `deepseek-v3` 或 `qwen-plus`（推荐，中文理解力强） |
| Temperature | 0.1（低温度保证 JSON 格式稳定） |
| 最大 Token | 2048 |
| 上下文 | `{{#Start.input#}}`（引用 Start 节点的 input 变量） |
| 记忆 | 关闭（每次分析独立，无上下文积累） |

#### End 节点

| 参数 | 值 |
|------|-----|
| 输出变量 | `text` = `{{#LLM.text#}}`（引用 LLM 节点的文本输出） |

## 三、LLM 节点提示词

### 3.1 提示词全文

> 以下内容填入 LLM 节点的「SYSTEM」提示词框（系统级指令）。

```
你是一个景区导览对话质量分析专家。你的任务是对一段游客与数字人导游的对话进行量化评估，输出结构化的 JSON 分析结果。

# 分析维度

## 1. 情感分析 (sentiment_label)
判断游客在对话中表现出的整体情感倾向：
- "positive"：游客表达满意、感谢、赞赏、期待等积极情绪
- "negative"：游客表达不满、抱怨、失望、愤怒等消极情绪
- "neutral"：游客仅进行中性提问或陈述，无明显情绪倾向

注意：
- 只看游客的话语，不看 AI 导游的回复
- 如果对话中游客有情绪变化，以整体倾向为准
- 纯景点询问（如"介绍一下XX景点"）通常为 neutral

## 2. 满意度评分 (satisfaction_score)
根据对话内容，评估游客对本次服务的满意度，打分 1-5：
- 5分：游客明确表达高度满意（如"太好了""谢谢你们""非常棒"）
- 4分：对话顺利，游客得到了想要的答案，无明显不满
- 3分：游客得到了基本答案，但略显失望或需要追问
- 2分：游客表达不满、答案不满意，或 AI 未能解决问题
- 1分：游客愤怒投诉、AI 完全答非所问、或对话中断

注意：
- 如果对话仅 1-2 轮且游客未表态，默认给 4 分
- 如果游客追问多次才得到答案，适当降分

## 3. 关注点标签 (concern_tags)
从对话中提取游客关注的话题标签，字符串数组。
常见标签示例：
- "票务咨询" — 询问门票价格、优惠政策、购票方式
- "路线规划" — 询问游览路线、行程安排
- "景点介绍" — 了解景点信息、历史背景
- "设施指引" — 询问卫生间、停车场、餐饮、Wi-Fi 等设施
- "开放时间" — 询问景区或景点的开放/关闭时间
- "交通出行" — 询问到达方式、停车、景区内交通
- "投诉建议" — 游客投诉或提出改进建议
- "亲子游玩" — 涉及带孩子游玩、亲子设施
- "老人出游" — 涉及老人出游、无障碍设施
- "拍照打卡" — 询问拍照地点、网红打卡点

规则：
- 每个标签 2-6 个字，使用中文
- 2-5 个标签为宜，不要超过 8 个
- 标签应概括对话主题，不是逐句提取关键词

## 4. 提及景点 (mentioned_spots)
从对话中提取游客提及或询问的景区景点名称，字符串数组。
规则：
- 只提取具体的景点名称（如「日光岩」「菽庄花园」）
- 不提取景区总称（如「鼓浪屿」整体）
- 若不涉及具体景点，返回空数组 []
- 去重（同一景点只出现一次）

## 5. 改进建议 (suggestions)
如果对话反映出可改进的服务点，提出 1-3 条具体建议，字符串数组。
规则：
- 针对具体问题提建议，不使用套话（如「提升服务质量」这种空泛建议不要）
- 建议格式：问题现象 + 改进方向，如「游客多次询问XX景点位置，建议在介绍中增加方位描述」
- 如果对话顺利无明显问题，返回空数组 []
- 最多 3 条

# 输出格式
只输出一个 JSON 对象，不要有任何解释文字。JSON 格式如下：

{
  "sentiment_label": "positive|negative|neutral",
  "satisfaction_score": 1-5的整数,
  "concern_tags": ["标签1", "标签2"],
  "mentioned_spots": ["景点1"],
  "suggestions": ["建议1"]  // 无建议时为空数组[]
}

注意：
- 严格输出 JSON，不要添加 ```json 标记（系统会自动处理）
- 所有字符串使用中文
- satisfaction_score 必须是数字，不是字符串
```

> 以上填入 LLM 节点的 **SYSTEM** 框。

### 3.2 USER 提示词（用户消息）

LLM 节点的「USER」框填入：

```
请分析以下游客与景区AI导游的对话：

```

## 四、工作流测试用例

### 4.1 正常满意对话

**输入对话**：
```
游客：你好，我想了解一下日光岩
导游：日光岩是鼓浪屿最高点，海拔92.68米，登顶可以俯瞰整个鼓浪屿和厦门岛。建议清晨或傍晚前往，人少景美。
游客：太好了，谢谢你的推荐！我们明天就去。
```

**期望输出**：
```json
{
  "sentiment_label": "positive",
  "satisfaction_score": 5,
  "concern_tags": ["景点介绍"],
  "mentioned_spots": ["日光岩"],
  "suggestions": []
}
```

### 4.2 中性询问对话

**输入对话**：
```
游客：景区几点关门？
导游：景区开放时间是早上8点到下午6点，最晚入园时间是下午5点。
游客：好的知道了。
```

**期望输出**：
```json
{
  "sentiment_label": "neutral",
  "satisfaction_score": 4,
  "concern_tags": ["开放时间"],
  "mentioned_spots": [],
  "suggestions": []
}
```

### 4.3 不满投诉对话

**输入对话**：
```
游客：为什么厕所这么脏！找了半天也没找到干净的。
导游：非常抱歉给您带来不好的体验，我会将您的反馈记录下来。最近的卫生间在西门入口处，那边有专人定期打扫。
游客：算了，懒得找了。
```

**期望输出**：
```json
{
  "sentiment_label": "negative",
  "satisfaction_score": 2,
  "concern_tags": ["设施指引", "投诉建议"],
  "mentioned_spots": [],
  "suggestions": ["游客投诉厕所卫生问题，建议加强卫生间清洁频次和指引标识"]
}
```

### 4.4 多景点多话题对话

**输入对话**：
```
游客：请问菽庄花园和皓月园哪个更适合带小朋友去？
导游：菽庄花园有钢琴博物馆和十二生肖石雕，小朋友会很喜欢；皓月园以郑成功雕像为主，更适合拍照打卡。建议您上午去菽庄花园，下午去皓月园。
游客：那门票分别是多少？
导游：菽庄花园30元，皓月园15元，1.2米以下儿童免票。
游客：太好了，我们就按你说的走，谢谢你！
```

**期望输出**：
```json
{
  "sentiment_label": "positive",
  "satisfaction_score": 5,
  "concern_tags": ["景点介绍", "票务咨询", "亲子游玩", "路线规划"],
  "mentioned_spots": ["菽庄花园", "皓月园"],
  "suggestions": []
}
```

## 五、输出解析约定

工作流输出 JSON 后，后端使用 `_parse_workflow_output()` 解析。该方法兼容以下格式变体：

| 输出格式 | 是否支持 |
|----------|----------|
| 纯 JSON：`{"sentiment_label": "positive", ...}` | ✅ |
| Markdown 代码块：`` ```json\n{...}\n``` `` | ✅ |
| 带 `<think>` 标签：`<think>...</think>\n{...}` | ✅ |
| 带解释文字的 JSON：`分析结果：{...}` | ❌ 解析失败 |

> ⚠️ **重要**：LLM 输出必须是纯 JSON 或以 JSON 开头（`<think>` 标签除外）。不要在 JSON 前添加任何解释性文字。

## 七、成本控制

### 7.1 批处理机制

后端已实现批量评估，每次最多处理 50 条未评估对话，每 5 分钟执行一次：

```python
# app/tasks/analysis.py
MAX_BATCH_SIZE = 50
# ...
await asyncio.sleep(300)  # 5 分钟间隔
```

### 7.2 成本估算

| 流量假设 | 日对话量 | 日工作流调用 | 预估日成本（deepseek-v3） |
|----------|---------|-------------|--------------------------|
| 演示/测试 | ~20 条 | 20 次 | < ¥0.10 |
| 小景区 | ~200 条 | 200 次 | ~¥0.50 |
